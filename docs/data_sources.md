# Data sources, provenance, and honest limitations

This project refuses to invent data. This document records where data comes from,
what it does and does not support, and the rules that keep historical tests honest.

## Price data

| Source | Status | Notes |
|---|---|---|
| **Bundled sample** (`data/sample/EURUSD_H1_sample.csv`) | **MOCK / synthetic** | Generated by `scripts/generate_sample_data.py`, seeded & reproducible. Tagged `source=MOCK`. **Not real market data.** Lets you run everything without a subscription. |
| Your own CSV | supported | Put a `timestamp` (UTC) + OHLC (+ optional bid/ask) file and pass `--data path.csv`. The `CsvPriceProvider` records provenance and runs quality checks. |
| QuantConnect data | future | Via LEAN (see `lean/`). Requires a QC account/data subscription. |
| Dukascopy / broker tick | future | Implement a `PriceDataProvider`; record source, timezone, bid/ask, gaps. |

**Quality checks** (`fxlab/data/quality.py`) report, for any dataset: time range,
bar count vs expected (completeness %), bid/ask availability, missing-period gaps
(weekends excluded), duplicate/non-monotonic timestamps, and structurally broken
bars (e.g. `high < low`). MOCK sources are flagged in every report.

**Timezones.** All data is stored in **UTC**. The system displays event times in
**America/Toronto**. FX has no single exchange; "sessions" (Asia/London/NY) are
modelled as UTC hour ranges — an approximation, stated as such.

## Economic-event data

| Provider | What it gives | Honesty flag |
|---|---|---|
| **sample** (bundled) | Curated MOCK high-impact events (CPI/NFP/FOMC-like) | `source=MOCK` |
| **FRED** (`fxlab/econ/fred_provider.py`) | **Official release DATES** for US CPI, Employment, GDP, Retail Sales | release date is official; intraday **time is conventional** → `time_is_exact=False` |

### The look-ahead rules for news (important)
1. Events are stored in UTC; nothing is usable in a backtest **before** its
   `time_utc`.
2. FRED provides the **date** a series is released, **not** a guaranteed intraday
   timestamp. We attach the well-known **conventional** US release time (e.g.
   08:30 ET for CPI/NFP, 14:00 ET for FOMC) and set `time_is_exact=False`.
3. When `time_is_exact=False`, the blackout window is **widened** by a safety
   margin, and we avoid precise event-driven logic. We do **not** fabricate a
   minute-accurate timestamp.
4. If you need minute-accurate historical event times (for tight, event-driven
   research), supply a **properly licensed** source with verified timestamps and
   set `time_is_exact=True`. Until then, keep event-driven historical features
   conservative. This is the intended behaviour, not a bug.
5. A news **summary may inform you**, but **no AI-generated prediction may place a
   trade.** The blackout rule only ever *blocks* trading; it never *triggers* it.

## Getting a FRED key (free, optional)
1. Create a free account and request a key at
   <https://fredaccount.stlouisfed.org/apikeys>.
2. Put it in `.env` as `FRED_API_KEY=...` (never commit it).
3. Set `provider: fred` in `config/news.yaml`. Without a key, the system silently
   falls back to the bundled sample events.
